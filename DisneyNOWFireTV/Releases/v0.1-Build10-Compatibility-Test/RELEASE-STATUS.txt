Build 10 is a targeted follow-up to the Build 9 physical debug report. The report showed repeated DisneyNOW HLS manifest detection while the WebView playback attempt failed, but no native-player attempt had been captured. Build 10 keeps the existing user-triggered Media3 path and adds privacy-safe visibility into the HLS/DASH -> native-player handoff.

New diagnostics include native-handoff readiness/attempt/player-create/prepare counters, a handoff-stage state machine, manifest host/type/age, safe session-context presence indicators, post-manifest non-GET host/method/content-type category counters, and Media3 error code plus exception class chain only. No cookies, tokens, request bodies, full protected-media/license URLs, DRM keys, or typed text are exported. WebView remote debugging remains disabled.

The Menu item now shows whether Try Native Player is waiting for a detected stream or ready with HLS/DASH. The first detected HLS/DASH stream per page can show a one-time hint directing the user to Menu > Try Native Player after WebView playback failure. Native playback remains user-triggered; Build 10 does not automatically hijack playback.
